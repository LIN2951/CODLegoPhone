# 迷恋塔罗

入口：微信 → 发现 → 情侣空间 → 已建立关系的私密空间 → 迷恋塔罗。

本模块直接集成公开项目的牌库、牌阵、粒子牌面、解读规则和结果合同，许可与精确版本见 `THIRD_PARTY_NOTICES.md` 和 `upstream-source.json`。手机采用 Canvas + CSS 翻牌、可滚动选牌池与顺序牌位卡，五种牌阵的牌位语义保持不变。

## 用户流程

写下问题 → 选择牌阵/正逆位 → 洗牌 → 手动选牌或代抽 → 抽齐后整组翻开 → 查看基础牌义 → 按需请求塔罗师/TA 视角。打开页面、抽牌、刷新和恢复均不自动请求模型。两种 AI 视角各自单独调用；不会自动发消息到微信。

## 独立边界

- 全部业务文件、界面、样式、上游资源、缓存管理、服务工作线程和测试位于本目录。宿主仅修改 `index.html` 入口/加载，以及 `app.js`、`wechat-backup.js` 的整体备份与清空接线。
- IndexedDB `LegoMilianTarotDB`：`sessions`、`preferences`。按好友 ID、用户人设 ID（没有 ID 时用昵称与身份文本）、关系建立时间计算 SHA-256 空间标识。切换人设/重新建立关系不会读取之前空间的记录；角色修改会取消当前页面的旧请求。
- Cache Storage `lego-milian-tarot-art-v2` 和 `lego-milian-tarot-static-v2`。`sw.js` 作用域仅本模块路径，严格缓存静态白名单，不缓存 API、密钥、问题、聊天或主应用页面。清缓存不清记录，清理覆盖本模块所有缓存版本。内存 Canvas 转 Blob 后释放，退出释放 Object URL。
- API 密钥仍由 Lego 主设置管理，模块只读取是否就绪/模型名称，不复制到模块数据、缓存或备份。TA 视角仅按用户点击带入该好友角色、用户身份、关联世界书和最近十条对话。
- 全牌序和正逆位在第一次选择前提交到 IDB；每次选牌、揭示、开始请求均确认事务提交。CAS 版本控制防止多标签页重复请求与覆盖，完成时核对持久化 requestId，删除不会被迟到结果复活。
- 请求 90 秒超时，关闭/切换时取消；110 秒持久化期限支持崩溃恢复。失败/中断标记为结果未知，可能已计费，绝不自动付费重试。收到结果但保存失败时可复制及重试保存，后者不再次调用模型。
- 每空间最多 500 条，不自动淘汰历史。独立导入最大 64 MB，完整校验牌库/牌位/正逆位/字段后原子合并；相同记录跳过、不覆盖较新本地内容。整体微信备份包含所有塔罗空间，旧版备份不删除塔罗数据。

## 开发与验证

`node --test modules/milian-tarot/tests/core.test.js` 运行纯规则测试。浏览器隔离验收入口由 `node modules/milian-tarot/tests/fixture-server.cjs` 提供，随机端口、虚构好友与 API，仅本机假响应，无真实用户数据或上游请求。

发布时本目录应与主页面一起分发。版本更新需同时调整入口/HTML 资源版本及 `sw.js`、`cache.js` 的静态缓存版本。此任务不包含构建 APK 或部署。
